#UML

linguagem visual utilizada para modelar sistemas computacionais or meio do paradigma de Orientação a Objetos
Não é uma linguagem de programação, mas de modelagem, simplificando o sistema real.

Um modelo é uma abstração da coisa real que permite entender, avaliar e criticar, por exemplo.

Auxiliar os engenheiros de software a definir características do
software:

• Requisitos;

• Comportamento;

• Estrutura lógica;

• Dinâmica dos processos;

• Necessidades físicas.

A modelagem pode possuir um diagrama que complementa os outros diagramas, assim como cada pode diagrama analisar o todo 
o sistema ou parte dele.

##Tipos

Estruturais - 
Arquitetura do modelo. Trabalha com classes objetos, interfaces, infraestrutura
Ex.: Diagrama de classes

Comportamentais - 
Trabalha com a interação, estados do modelo
ex.: Diagramas de caso de uso

#Diagrama de caso de uso

Linguagem mais simples possibilitar a compreensão do comportamento externo do sistema. 
Ele permite a compreensão de ambos os lados, cliente e desenvolvedor, e pode/deve ser apresentado durante as reuniões 
iniciais com os clientes.

Os casos de uso são utilizados para capturar requisitos do
sistema:

• Serviços;

• Tarefas;

• Funcionalidades.

Temos os atores que representam os papeis desempenhados pelos
diversos usuários que poderão utilizar os serviços e funções
do sistema. Podem eventualmente representar um
hardware ou software que interaja com o sistema. Além disso existem também 
associações que representam relações, interações ou relacionamentos.

##Tipos

1. Primários
   
2. Secundários

##Especialização/generalização

Diz respeito a associação entre casos de uso ou atores com
características semelhantes, mas que apresentam diferenças entre
si. Assemelha-se ao conceito de herança. Estes são dados por setas

Inclusão:

Indica obrigatoriedade “Se A inclui B, obrigatoriamente B deve ser executado também”.
